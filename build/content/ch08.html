تصميم قاعدة البيانات مع PostgreSQL

الجداول والعلاقات والفهارس والمهاجرات: مخطط واحد يوافق عليه الفريق كله

قاعدة البيانات هي الذاكرة طويلة المدى للنظام. في هذا الفصل نُثبّت مخططاً واحداً (schema) ونكتب أول migration تنشئه في PostgreSQL، فيبني أي عضو القاعدة بأمر واحد.

8.1 مبادئ التصميم التي نلتزم بها

ستة مبادئ تحكم كل قرار تصميمي في هذا الفصل.

جدول 8-1: مبادئ تصميم قاعدة البيانات
المبدأالمعنى العملي
المفتاح الأساسي Primary Key لكل جدول عمود id فريد لا يتغيّر. الجداول "الكبيرة" (مثل videos و incidents) تستخدم UUID لأنها تظهر في مسارات الـ API، وجداول الأحداث الكثيفة (detections، tracks) تستخدم BIGSERIAL لأن كتابتها سريعة وترقيمها المتزايد لا يُعرض للمستخدم.
المفتاح الأجنبي Foreign Key كل علاقة بين جدولين تُعبَّر عنها بمفتاح أجنبي صريح مع قاعدة حذف واضحة، حتى يمنع PostgreSQL البيانات المعلّقة (orphan rows).
الفهرس Index لا نضيف فهرساً "للتأمين"، بل لكل استعلام نعرف أننا سنستخدمه فعلاً في الفلترة أو الترتيب.
الطوابع الزمنية Timestamps كل جدول مهم يحمل created_at، والجداول القابلة للتعديل تحمل أيضاً updated_at. النوع دائماً TIMESTAMPTZ مع المنطقة الزمنية.
القيد Constraint القيم المحدودة (الحالات، الأنواع، الأدوار) تُخزَّن كـ enum أصلي، فلا يمكن إدخال حالة غير معروفة حتى لو أخطأ الكود.
لا تخزين باينري الفيديو والصور لا تُخزَّن داخل PostgreSQL؛ نخزّن البيانات الوصفية (metadata) والمفتاح storage_key فقط.

8.2 الـ Enums: القيم المسموح بها فقط

ثمانية أنواع تعدادية (enum) بدل النصوص الحرة، فلا يمكن كتابة حالة غير معروفة. القيم التالية حرفية ومطابقة لعقد الـ API في الفصل 7.

8.7 نمو جدول detections وخيار PERSIST_ALL_DETECTIONS

فيديو عشر دقائق = 15000 إطار؛ تسجيل كل كشف يُنشئ ملايين الصفوف بلا فائدة، فالمهمّ الوقائع لا كل كشف.

  • الافتراضي: PERSIST_ALL_DETECTIONS=false، فلا نكتب إلا الكشوفات المهمّة أو عيّنات منها.
  • عند التفعيل: PERSIST_ALL_DETECTIONS=true للتطوير والتشخيص فقط.
  • الربط: قرار الكتابة داخل الـ worker (الفصل 11)، لا داخل الـ Model.
تنبيه عملي

ابدأ بالقيمة الافتراضية، وارفعها مؤقتاً فقط عند تحقيقك في مشكلة كشف، وتجنّبها على جهاز ضعيف أو قرص ممتلئ.

8.8 لماذا لا نخزّن الفيديو داخل PostgreSQL

لماذا لا نضع الفيديو في حقل BYTEA؟ لأن حجمه يضخّم النسخ الاحتياطي والاستعلام. نحفظ وصفاً صغيراً فقط، ويبقى الملف في نظام ملفات أو تخزين كائنات مستقل.

جدول 8-12: أين يوضع كل شيء
البياناتمكانهاالسبب
البيانات الوصفية (original_filename، size_bytes، status)PostgreSQLصغيرة، قابلة للفلترة والفهرسة
ملف الفيديو نفسهطبقة التخزين storage/كبير جداً، لا يحتاج استعلاماً

8.9 Alembic والمهاجرات الأولى

Alembic أداة المهاجرات (migrations) لـ SQLAlchemy: تحوّل تعريفات الـ Models إلى تغييرات فعلية، فيعيد أي عضو بناء المخطط بأمر واحد.

backend/app/models/video.pypython
# backend/app/models/video.py (abbreviated)
import uuid
from sqlalchemy import BigInteger, DateTime, Enum, ForeignKey, Integer, Numeric, String, func
from sqlalchemy.dialects.postgresql import UUID
from sqlalchemy.orm import Mapped, mapped_column, relationship
from app.db.base import Base
from app.models.enums import VideoStatus


class Video(Base):
    __tablename__ = "videos"

    id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    camera_id: Mapped[uuid.UUID | None] = mapped_column(ForeignKey("cameras.id"))
    original_filename: Mapped[str] = mapped_column(String(255), nullable=False)
    stored_filename: Mapped[str] = mapped_column(String(255), nullable=False)
    storage_key: Mapped[str] = mapped_column(String(512), unique=True)
    content_type: Mapped[str] = mapped_column(String(100))
    size_bytes: Mapped[int] = mapped_column(BigInteger)
    duration_seconds: Mapped[float | None] = mapped_column(Numeric(10, 3))
    fps: Mapped[float | None] = mapped_column(Numeric(8, 3))
    frame_count: Mapped[int | None] = mapped_column(Integer)
    checksum_sha256: Mapped[str | None] = mapped_column(String(64), index=True)
    status: Mapped[VideoStatus] = mapped_column(
        Enum(VideoStatus, name="video_status"), default=VideoStatus.uploaded)
    uploaded_by: Mapped[uuid.UUID | None] = mapped_column(ForeignKey("users.id"))
    created_at: Mapped[None] = mapped_column(DateTime(timezone=True), server_default=func.now())
    updated_at: Mapped[None] = mapped_column(DateTime(timezone=True), server_default=func.now(), onupdate=func.now())

    jobs = relationship("ProcessingJob", back_populates="video", cascade="all, delete-orphan")
    incidents = relationship("Incident", back_populates="video")

بعد الأمر الأخير تطابق القاعدة المخطط. --autogenerate يولّد المهاجرة بمقارنة الـ Models بالوضع الحالي، ومراجعتها يدوياً إلزامية.

8.10 الخصوصية: لا نخزّن هويات حقيقية للعاملين

لا نحتاج معرفة من هو العامل، فلا نخزّن أسماء ولا صوراً تعريفية ولا أرقام هوية، بل track_id مؤقّتاً وصور دليل للمراجعة.

ملاحظة للجنة المناقشة

النظام يحفظ أدلة بصرية للحدث لا هويات أشخاص، ويساعد المراجعة البشرية لا التعقّب الفردي.

خلاصة الفصل 8

ما تعلّمناه

ثبّتنا مخطط قاعدة البيانات كاملاً: ثمانية enums، وجداول الـ MVP الثمانية، وثلاثة جداول مؤجَّلة، وعلاقات 1..N، والفهارس المرتبطة بالفلترة، وسبب عدم تخزين الفيديو داخل PostgreSQL، وكيف نُدير كل ذلك بـ Alembic.

ما يجب تنفيذه

  • كتابة app/models/enums.py بكل القيم الثمانية حرفياً.
