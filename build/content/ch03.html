حزمة التقنيات واختيار الأدوات

لماذا اخترنا كل أداة، وما البدائل، وما هو مطلوب في الـ MVP

اختيار التقنية ليس "أيّ شيء يعمل"، بل قرار يجب أن نبرّره. يعرض هذا الفصل كل أداة، ووظيفتها، وسبب اختيارها، وحالتها (MVP أم اختيارية)، وبديلها، حتى يكون كل عضو قادراً على الدفاع عن كل قرار أمام لجنة المناقشة.

3.1 معايير اختيار التقنية

طبّقنا خمسة معايير على كل خيار: الملاءمة للمهمة (هل الأداة مصمَّمة لهذا العمل؟)، التوفّر والتوثيق الرسمي الجيد، سهولة التعلّم لعضو مبتدئ، التكامل مع بقية الحزمة، والتشغيل المحلي بلا تعقيد أو تكلفة.

3.3 لماذا Python للـ Backend وللذكاء الاصطناعي معاً

Python: لغة عالية المستوى تُقرأ كالإنجليزية تقريباً. اخترناها لأن عالم الذكاء الاصطناعي مبني حولها (PyTorch وUltralytics وOpenCV كلها مكتبات Python)، فلو اخترنا لغة أخرى للـ Backend لاحتجنا عمليتين بلغتين والتنسيق بينهما. النسخة المستهدفة Python 3.11، ونستخدم venv لعزل مكتبات المشروع عن مكتبات النظام.

3.4 حزمة الذكاء الاصطناعي والرؤية الحاسوبية

  • PyTorch: المحرّك الذي يشغّل أوزان الشبكات، والأكثر استخداماً في المراجع.
  • Ultralytics YOLO: كشف الأجسام بدالة واحدة، وتوفّر تتبّعاً جاهزاً عبر model.track فلا نكتب منطق الشبكة بأنفسنا.
  • ByteTrack: تتبّع يمنح كل شخص معرّفاً ثابتاً عبر الإطارات لنحسب مدة المخالفة.
  • OpenCV: قراءة الفيديو واستخراج الإطارات وتغيير الحجم وكتابة صور الدليل.
  • NumPy: العمليات العددية وحساب التداخل والمسافات. Pandas: تجميع الوقائع للتقارير والتصدير.

3.5 حزمة الـ Backend وقاعدة البيانات

  • FastAPI: يبني الـ API بسرعة ويولّد توثيق Swagger تلقائياً من الأنواع، مع تحقق آلي من المدخلات. Uvicorn: الخادم الذي يشغّله بأمر uvicorn app.main:app --reload.
  • Pydantic v2: يتحقق من شكل البيانات عبر نماذج بأنواع صريحة، و pydantic-settings يقرأ متغيّرات البيئة في كائن إعدادات واحد.
  • SQLAlchemy 2.0: يربط Python بـ PostgreSQL ويعرّف الجداول كأصناف. Alembic: يتتبّع تغييرات المخطط كملفات migration قابلة للتطبيق والتراجع.
  • PostgreSQL 16: تدعم UUID والأنواع والعناصر الجزئية الفريدة (partial unique index) التي نحتاجها لمنع مهمّتين على نفس الفيديو. اخترناها على SQLite لأن الأخيرة لا تكفي لبيئة متعددة العمليات.
  • psycopg (v3): المشغّل الذي يربط SQLAlchemy بـ PostgreSQL.
  • JWT + bcrypt: مصادقة اختيارية خلف AUTH_ENABLED؛ الـ JWT رمز دخول موقَّع، وbcrypt تجزئة كلمات المرور فلا تُخزَّن كنص صريح.

3.6 حزمة الـ Frontend وأدوات التطوير

  • React 18: بناء الواجهة من مكوّنات قابلة لإعادة الاستخدام. TypeScript 5: أنواع صريحة تكشف الأخطاء قبل التشغيل. Vite 5: تشغيل وبناء سريع بتحديث فوري.
  • Tailwind CSS 3 للتنسيق، Recharts للمخططات، Axios لطلبات HTTP، react-router-dom v6 للتنقل.
  • Git + GitHub لتتبّع الإصدارات والتعاون عبر فروع وPull Requests، و VS Code كمحرّر مع إضافات Python وESLint وTailwind.
  • Node.js + npm لبيئة الـ Frontend، وvenv لبيئة الـ Backend.
  • Docker لحزم التطبيق، وDocker Compose لتشغيل عدة حاويات بأمر واحد عبر docker-compose.yml. GitHub Actions مؤجَّلة لما بعد الـ MVP.

3.7 ما لا نستخدمه في الـ MVP ولماذا

قرار "ما لا نستخدمه" لا يقل أهمية؛ كل تقنية إضافية تستهلك وقت الفريق وتعقّد التشغيل.

3.8 ملاحظة عن أرقام الإصدارات

الإصدارات المذكورة نقطة بداية لا وعد نهائي. القاعدة: تحقّق دائماً من أحدث إصدار مستقر من المصادر الرسمية (PyPI وnpm والتوثيق الرسمي) قبل التثبيت في ملفات المتطلبات، وعند التعارض نختار الإصدار الذي يتوافق معه أكبر عدد من المكتبات الأساسية (PyTorch وUltralytics أولاً).

خلاصة الفصل 3

ما تعلّمناه

عرفنا كل أداة: وظيفتها وسبب اختيارها وحالتها وبديلها. وثبّتنا أن Python تخدم الـ Backend والذكاء الاصطناعي معاً، وأن FastAPI وPostgreSQL وReact أعمدة الحزمة، وأن مجموعة تقنيات شهيرة مرفوضة في الـ MVP.

ما يجب تنفيذه

  • تثبيت الإصدارات في backend/requirements.txt وfrontend/package.json.
  • التحقق من أحدث إصدار مستقر لكل مكتبة أساسية من المصدر الرسمي.
  • تأجيل كل تقنيات جدول 3-2 حتى إشعار مكتوب.

المخرجات المتوقعة

  • ملف backend/requirements.txt بإصدارات مثبَّتة.
  • ملف frontend/package.json بإصدارات مثبَّتة.
  • وثيقة docs/STACK.md تضم جدول 3-1 وتبرير كل اختيار.

كيف نتحقق من الإنجاز

  • كل عضو يشرح لماذا اخترنا FastAPI لا Flask، وPostgreSQL لا SQLite.
  • لا مكتبة في المشروع بدون مبرّر مكتوب.
  • لا رقم إصدار غير موثّق من مصدر رسمي.

أخطاء شائعة

  • إضافة Redis أو Celery بلا حاجة فعلية.
  • تثبيت إصدارات قديمة من درس قديم دون تحقق.
  • تشغيل الـ Model داخل عملية الـ API مباشرة.
