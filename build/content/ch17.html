التحليلات وتقارير الالتزام والتصدير

كل رقم في اللوحة يجب أن يأتي من صف مخزَّن في قاعدة البيانات

التحليلات ليست رسوماً تجميلية، بل إجابة عن أسئلة السلامة: كم واقعة حدثت؟ وفي أي نوع؟ وما خطورتها؟ وما زال ينتظر المراجعة؟ هذا الفصل يبني كل هذه الأرقام من صفوف حقيقية في PostgreSQL، ويصدّرها كملف CSV قابل للمشاركة.

17.1 مبدأ واحد: كل رقم من صف مخزَّن

ممنوع كتابة أي رقم في الكود. المؤشرات تُحسب بـ SQL عبر استعلامات تجميع (aggregation) على جداول incidents وvideos وprocessing_jobs. الفائدة أن اللوحة تتغيّر تلقائياً مع كل واقعة جديدة دون أي تعديل في الكود. الاستعلامات كلها مقيدة بالفلترة بالتاريخ والفيديو والنوع، حتى تُعرض نفس الأرقام لمدى زمني مختلف دون كتابة مسار جديد.

17.2 خدمة التحليلات واستعلاماتها

الخدمة تُرجع كائناً مطابقاً حرفياً لـ AnalyticsOverview، وتُبني كل حقول incidents_by_type / by_severity / by_status من مجموعة تجميع واحدة لكل بعد.

backend/app/services/analytics_service.pypython
from sqlalchemy import func, select
from sqlalchemy.orm import Session

from app.models.incident import Incident
from app.models.processing_job import ProcessingJob
from app.models.video import Video


def _count_by(db: Session, column):
    rows = db.execute(select(column, func.count()).group_by(column)).all()
    return {str(key): int(count) for key, count in rows}


def get_overview(db: Session) -> dict:
    total_videos = db.scalar(select(func.count()).select_from(Video)) or 0
    processed = db.scalar(
        select(func.count()).select_from(Video).where(Video.status == "processed")
    ) or 0
    total_incidents = db.scalar(select(func.count()).select_from(Incident)) or 0
    pending = db.scalar(
        select(func.count()).select_from(Incident).where(Incident.status == "pending_review")
    ) or 0
    jobs_running = db.scalar(
        select(func.count()).select_from(ProcessingJob).where(ProcessingJob.status == "running")
    ) or 0
    jobs_failed = db.scalar(
        select(func.count()).select_from(ProcessingJob).where(ProcessingJob.status == "failed")
    ) or 0
    last_incident_at = db.scalar(select(func.max(Incident.created_at)))
    return {
        "total_videos": int(total_videos),
        "processed_videos": int(processed),
        "total_incidents": int(total_incidents),
        "incidents_by_type": _count_by(db, Incident.incident_type),
        "incidents_by_severity": _count_by(db, Incident.severity),
        "incidents_by_status": _count_by(db, Incident.status),
        "pending_review": int(pending),
        "jobs_running": int(jobs_running),
        "jobs_failed": int(jobs_failed),
        "last_incident_at": last_incident_at,
    }

backend/app/services/analytics_service.py (timeseries)python
def get_timeseries(db: Session, date_from, date_to) -> list[dict]:
    day = func.date(Incident.created_at).label("day")
    rows = db.execute(
        select(day, Incident.incident_type, func.count())
        .where(Incident.created_at >= date_from, Incident.created_at < date_to)
        .group_by(day, Incident.incident_type)
    ).all()
    buckets: dict[str, dict] = {}
    for d, itype, count in rows:
        point = buckets.setdefault(
            str(d), {"date": str(d), "ppe_violation": 0, "fire_smoke": 0,
                     "machine_proximity": 0, "total": 0}
        )
        point[itype] += int(count)
        point["total"] += int(count)
    return sorted(buckets.values(), key=lambda p: p["date"])

17.3 الملخص اليومي والمخالفات المتكررة

الملخص اليومي هو تجميع بسيط على التاريخ والنوع والخطورة والحالة، ويُستخدم في صفحة التقارير وفي التصدير معاً، فلا يوجد منطق مكرَّر. أما المخالفات المتكررة فتُكتشف بالعدّ حسب zone_name أو class_name، أو بإعادة عدّ وقائع نفس video_id خلال فترة.

17.4 مسار تصدير CSV

التصدير يعيد text/csv مباشرة، مع ترويسة Content-Disposition التي تجعل المتصفح ينزّل الملف. نكتب الصفوف من نفس دالة الملخص اليومي، ونجبر الترميز على utf-8-sig حتى تظهر العربية سليمة في Excel.

backend/app/api/v1/endpoints/reports.pypython
import csv
import io

from fastapi import APIRouter, Depends
from fastapi.responses import StreamingResponse
from sqlalchemy.orm import Session

from app.db.session import get_db
from app.services.analytics_service import get_daily_rows

router = APIRouter(prefix="/reports", tags=["reports"])


@router.get("/daily")
def daily(date_from: str | None = None, date_to: str | None = None,
          incident_type: str | None = None, db: Session = Depends(get_db)):
    return get_daily_rows(db, date_from, date_to, incident_type)


@router.get("/export")
def export_csv(date_from: str | None = None, date_to: str | None = None,
               incident_type: str | None = None, db: Session = Depends(get_db)):
    rows = get_daily_rows(db, date_from, date_to, incident_type)
    buffer = io.StringIO()
    writer = csv.writer(buffer)
    writer.writerow(["date", "incident_type", "severity", "status", "count"])
    for r in rows:
        writer.writerow([r["date"], r["incident_type"], r["severity"], r["status"], r["count"]])
    content = buffer.getvalue().encode("utf-8-sig")
    return StreamingResponse(
        iter([content]),
        media_type="text/csv",
        headers={"Content-Disposition": "attachment; filename=safevision-report.csv"},
    )

17.5 تنزيل الملف في الواجهة

نطلب الملف بـ responseType: "blob"، ثم ننشئ رابطاً مؤقتاً ونضغط عليه برمجياً، ونحرّر الرابط بعد ذلك لتوفير الذاكرة. لا نحاول قراءة CSV كأنه JSON.

frontend/src/api/reports.tstypescript
import { api } from "./client";

export interface ReportParams {
  date_from?: string;
  date_to?: string;
  incident_type?: string;
  video_id?: string;
}

export async function downloadReportCsv(params: ReportParams) {
  const res = await api.get("/api/v1/reports/export", {
    params,
    responseType: "blob",
  });
  const url = URL.createObjectURL(res.data as Blob);
  const link = document.createElement("a");
  link.href = url;
  link.download = "safevision-report.csv";
  link.click();
  URL.revokeObjectURL(url);
}

17.6 البيانات الاصطناعية والوسم الواضح

لا أرقام وهمية بلا وسم

قبل توفر بيانات حقيقية كافية، يجوز استخدام بيانات اصطناعية (synthetic demo data) لعرض الشكل فقط، بشرط أن تكون في جدول أو ملف منفصل بوضوح، وأن يظهر على الشاشة وسم مثل "بيانات تجريبية اصطناعية". يُمنع خلط الأرقام الاصطناعية ببيانات حقيقية في نفس البطاقة، ويُمنع تقديمها كأنها نتائج قياس فعلية.

17.7 PDF كخيار مستقبلي

تصدير PDF مفيد للإدارة لكنه يحتاج مكتبة إضافية وتحكّماً في التخطيط، لذا نتركه Future. الـ CSV يكفي الـ MVP: يُفتح في Excel، ويمكن بناؤه من نفس صفوف الملخص دون منطق جديد.

خلاصة الفصل 17

ما تعلّمناه

حسبنا المؤشرات كلها من صفوف مخزَّنة عبر استعلامات تجميع، وبنينا الاتجاه الزمني بشكل TimeseriesPoint، وصمّمنا مسار تصدير CSV، وكتبنا كود التنزيل، ووضعنا ضوابط للبيانات الاصطناعية، وأجّلنا PDF.

ما يجب تنفيذه

  • كتابة استعلامات التحليلات والتحقق من أسمائها مقابل SPEC.
  • ربط صفحة التقارير بمسار /reports/daily وزر التصدير.
  • إضافة وسم صريح لأي بيانات اصطناعية.
  • التحقق من ظهور العربية سليمة في ملف CSV.

المخرجات المتوقعة

  • لوحة تعرض أرقاماً تتغيّر مع كل واقعة جديدة.
  • ملف CSV قابل للفتح في Excel بعربية سليمة.
  • فلترة بالنطاق الزمني والنوع والفيديو تعمل على الخادم.

كيف نتحقق من الإنجاز

  • إضافة واقعة يدوياً تغيّر أرقام اللوحة.
  • لا يوجد رقم ثابت مكتوب في الـ service.
  • الملف المُنزَّل يطابق صفوف /reports/daily.

أخطاء شائعة

  • حساب المؤشرات في الواجهة من صفحة واحدة بدل الخادم.
  • نسيان الفلترة فيرجع الرقم لكامل البيانات.
  • عرض أرقام اصطناعية دون وسم.
  • معالجة CSV كنص عادي فيتلف عند التنزيل.
