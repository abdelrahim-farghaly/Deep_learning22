CH05 · ENVIRONMENT SETUP

تجهيز بيئة التطوير

من جهاز فارغ إلى Backend و Frontend يعملان ويتحدثان معاً

هذا الفصل عملي بالكامل. الهدف أن يصل كل عضو من جهاز فارغ إلى نظام يعمل: الـ Backend يرد على الطلبات، والـ Frontend يعرض البيانات، والاثنان يتحدثان معاً. نُقدّم أوامر كاملة قابلة للنسخ، بنسخة Windows PowerShell أولاً ثم بدائل Linux / macOS.

5.1 مفاهيم أساسية قبل البدء

  • Terminal: نافذة نصية نكتب فيها الأوامر. في Windows نستخدم PowerShell، وفي Linux/macOS نستخدم Bash.
  • Working Directory: المجلد الحالي الذي ينفّذ فيه الطرفية الأوامر. الأوامر النسبية تُحسب منه، لذا يجب التأكد من مكاننا قبل التنفيذ.
  • Port: رقم يحدّد الخدمة على الجهاز. الـ Backend يعمل على 8000، والـ Frontend على 5173، وPostgreSQL على 5432. لا يمكن لخدمتين استخدام نفس المنفذ.
  • Environment Variable: متغيّر يُخزَّن خارج الكود ليحمل الإعدادات والأسرار. نضعها في ملف .env ولا نرفعه إلى Git.

5.3 الخطوات الاثنا عشر خطوة بخطوة

الخطوة 1: إنشاء المستودع محلياً

terminalpowershell
$ git clone https://github.com/<YOUR_ORG>/safevision-ai.git
$ cd safevision-ai

الخطوة 2: إنشاء البيئة الافتراضية

ننشئ venv في جذر المشروع لعزل مكتبات الـ Backend عن النظام.

terminalpowershell / bash
# Windows PowerShell
$ python -m venv .venv

# Linux / macOS
$ python3 -m venv .venv

الخطوة 3: تنشيط البيئة الافتراضية

terminalpowershell / bash
# Windows PowerShell
$ .venv\Scripts\Activate.ps1
# If script execution is blocked, run this once for the current session:
$ Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

# Linux / macOS
$ source .venv/bin/activate

الخطوة 4: تثبيت متطلبات الـ Backend

terminalpowershell / bash
$ cd backend
$ pip install --upgrade pip
$ pip install -r requirements.txt

الخطوة 5: إنشاء تطبيق React بـ Vite و TypeScript

إن كان مجلد frontend فارغاً نُنشئ فيه مشروع Vite بقالب TypeScript.

terminalpowershell / bash
$ cd ../frontend
$ npm create vite@latest . -- --template react-ts
$ npm install

الخطوة 6: تثبيت متطلبات الـ Frontend

terminalpowershell / bash
$ npm install axios react-router-dom recharts
$ npm install -D tailwindcss postcss autoprefixer
$ npx tailwindcss init -p

الخطوة 7: إعداد ملف .env

ننسخ القالب ثم نملأ القيم الحقيقية محلياً (كلمة مرور قاعدة البيانات، مسارات الـ checkpoints).

terminalpowershell / bash
# Windows PowerShell
$ Copy-Item .env.example .env

# Linux / macOS
$ cp .env.example .env

الخطوة 8: تشغيل PostgreSQL

الطريقة الموصى بها عبر Docker Compose، والبديل تشغيل حاوية مباشرة.

terminalpowershell / bash
# Preferred: start the database service from docker-compose.yml
$ docker compose up -d db

# Alternative: run a single PostgreSQL 16 container
docker run --name safevision-db -d -p 5432:5432 ^
  -e POSTGRES_USER=<DB_USER> -e POSTGRES_PASSWORD=<DB_PASSWORD> ^
  -e POSTGRES_DB=safevision postgres:16

الخطوة 9: تشغيل الـ Backend

terminalpowershell / bash
$ cd backend
$ uvicorn app.main:app --reload --port 8000

الخطوة 10: تشغيل الـ Frontend

نفتح طرفية ثانية ونترك الأولى تعمل.

terminalpowershell / bash
$ cd frontend
$ npm run dev

الخطوة 11: فتح توثيق Swagger

افتح في المتصفح http://localhost:8000/docs لتظهر كل الـ Endpoints وتجربتها مباشرة.

الخطوة 12: التأكد من التواصل

نتأكد أن الـ Backend يرد، وأن الـ Frontend يصل إليه عبر VITE_API_BASE_URL.

terminalpowershell / bash
$ curl http://localhost:8000/api/v1/health
# expected: {"status":"ok"}

خلاصة الفصل 5

ما تعلّمناه

فهمنا الطرفية ومجلد العمل والمنافذ ومتغيّرات البيئة، وتحقّقنا من الأدوات الست، ونفّذنا الخطوات الاثنتي عشرة من الاستنساخ حتى تأكيد التواصل، وعرفنا حلول أكثر أخطاء الإعداد شيوعاً.

ما يجب تنفيذه

  • تثبيت الأدوات الست والتحقق من إصداراتها.
  • إنشاء .venv وتنشيطه وتثبيت المتطلبات.
  • نسخ .env.example إلى .env وملء القيم.
  • تشغيل PostgreSQL ثم الـ Backend ثم الـ Frontend.
  • التأكد من رد /api/v1/health بلا أخطاء CORS.

المخرجات المتوقعة

  • جهاز كل عضو يشغّل النظام كاملاً محلياً.
  • Swagger يعمل على http://localhost:8000/docs.
  • الـ Frontend يعرض بيانات قادمة من الـ Backend فعلاً.

كيف نتحقق من الإنجاز

  • الأمر curl http://localhost:8000/api/v1/health يعيد status ok.
  • لا يوجد خطأ CORS في وحدة تحكّم المتصفح.
  • المنافذ 8000 و5173 و5432 مفتوحة وتعمل معاً.

أخطاء شائعة

  • تثبيت المكتبات في بيئة النظام بدل .venv.
  • نسيان تشغيل قاعدة البيانات قبل الـ Backend.
  • تعديل .env.example بقيم حقيقية بدل .env.
  • إغلاق طرفية الـ Backend أثناء العمل على الـ Frontend.
