الأمان والخصوصية والمصادقة

أمان عملي لمشروع طلابي صناعي، بدون مبالغة وبدون ثغرات واضحة

النظام يتعامل مع فيديو أماكن عمل، والخطأ الأمني فيه لا يهدّد البيانات فقط بل خصوصية العاملين. هذا الفصل يضع حدّاً أدنى صلباً من الأمان: كلمات مرور مشفَّرة، توكن صالح، أدوار محدودة، رفع محكم، أسرار خارج الكود، وخصوصية محفوظة بعدم التعرف على الوجوه. الهدف عملي: لا ثغرة واضحة، ودون تعقيد يعطّل الـ MVP.

18.1 المصادقة مقابل التصريح

المصادقة (Authentication): مَن أنت؟ تُتحقّق من هوية المستخدم عبر بريد وكلمة مرور. التصريح (Authorization): ما المسموح لك فعله؟ يُحدَّد بدورك في النظام. الخطأ الشائع هو الخلط بينهما، فيكفي تسجيل الدخول لأداء أي إجراء.

18.2 تشفير كلمات المرور

لا تُخزَّن كلمة المرور أبداً كنص صريح. نستخدم bcrypt الذي يضيف salt عشوائياً لكل كلمة، فيستحيل مقارنة الهاشين لكلمتين متطابقتين، ويصبح كسر الهاش مكلفاً. عمود القاعدة hashed_password يحمل الهاش فقط.

backend/app/core/security.pypython
# backend/app/core/security.py
from datetime import datetime, timedelta, timezone

import bcrypt
import jwt

from app.core.config import settings


def hash_password(plain: str) -> str:
    return bcrypt.hashpw(plain.encode("utf-8"), bcrypt.gensalt()).decode("utf-8")


def verify_password(plain: str, hashed: str) -> bool:
    return bcrypt.checkpw(plain.encode("utf-8"), hashed.encode("utf-8"))


def create_access_token(subject: str, role: str) -> str:
    expire = datetime.now(timezone.utc) + timedelta(
        minutes=settings.ACCESS_TOKEN_EXPIRE_MINUTES
    )
    payload = {"sub": subject, "role": role, "exp": expire}
    return jwt.encode(payload, settings.SECRET_KEY, algorithm=settings.JWT_ALGORITHM)


def decode_token(token: str) -> dict:
    return jwt.decode(token, settings.SECRET_KEY, algorithms=[settings.JWT_ALGORITHM])

18.3 التوكن والاعتماديات والتصريح بالأدوار

الـ JWT توكن موقَّع يحتوي هوية المستخدم ودوره ووقت انتهائه. الـ dependency get_current_user تُستخدم في كل مسار محمي، وتتجاوز المصادقة عند إيقاف العلم. ثم require_role يمنع الأدوار غير المصرّح لها.

backend/app/api/deps.pypython
from fastapi import Depends, HTTPException, status
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer
from sqlalchemy.orm import Session

from app.core.config import settings
from app.core.security import decode_token
from app.db.session import get_db
from app.models.user import User

bearer = HTTPBearer(auto_error=False)
DEFAULT_USER = {"id": None, "email": "demo@safevision.local", "role": "safety_officer"}


def get_current_user(
    creds: HTTPAuthorizationCredentials | None = Depends(bearer),
    db: Session = Depends(get_db),
):
    if not settings.AUTH_ENABLED:
        return DEFAULT_USER  # MVP demo mode
    if creds is None:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Missing token")
    try:
        payload = decode_token(creds.credentials)
    except Exception:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Invalid token")
    user = db.get(User, payload["sub"])
    if user is None or not user.is_active:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Inactive user")
    return user


def require_role(*roles: str):
    def checker(user=Depends(get_current_user)):
        role = user["role"] if isinstance(user, dict) else user.role
        if settings.AUTH_ENABLED and role not in roles:
            raise HTTPException(status.HTTP_403_FORBIDDEN, "Insufficient role")
        return user
    return checker

18.4 أمان رفع الملفات

الرفع هو أكبر مدخل خطر لأنه يستقبل ملفاً من خارج النظام. نطبّق عليه قيوداً متراكبة:

  • حد الحجم: نرفض ما يتجاوز MAX_UPLOAD_MB ونعيد 413 بدل إسقاط الاتصال.
  • الامتداد والمحتوى: نتحقق من ALLOWED_VIDEO_EXTENSIONS ومن magic bytes ومن فتح الملف بـ OpenCV (تفصيله في الفصل 9).
  • أسماء الملفات: لا نستخدم الاسم الأصلي على القرص أبداً؛ نولّد اسم UUID ونبني storage_key منه، وهذا يمنع path traversal.
  • عدم التنفيذ: مجلّدات التخزين لا تُخدَم كملفات تنفيذية، والوصول للفيديو والدليل يمرّ عبر endpoint يتحقق من الصلاحية بدل كشف المسار المباشر.

18.5 تقييد CORS والتحقق من المدخلات ومنع SQL Injection

  • CORS: نسمح فقط بأصول الواجهة المحدَّدة في CORS_ORIGINS، ولا نستخدم "*" في الإنتاج.
  • التحقق من المدخلات: كل جسم طلب يمرّ على مخطط Pydantic، وكل معامل استعلام محدَّد النوع، فالفشل يعيد 422 قبل الوصول للمنطق.
  • منع SQL Injection: نستخدم SQLAlchemy مع معاملات مرتبطة (bound parameters) ولا نُركّب نصوص SQL يدوياً، فلا يمكن للمدخل أن يغيّر الاستعلام.
  • Rate limiting: غير ضروري في العرض المحلي، لكن يُضاف على /auth/login عند النشر العام لمنع التخمين المتكرّر.

18.6 إدارة الأسرار

18.7 الخصوصية: تتبّع مجهول بلا تعرّف على الوجوه

لا تعرّف على الوجوه

النظام لا يستخدم التعرف على الوجوه ولا يخزّن هويات حقيقية للعاملين. الـ track_id مجرّد رقم مؤقت داخل فيديو واحد لربط كشوفات الشخص نفسه في الإطارات المتتالية؛ هو ليس هوية ولا يمكن ربطه بشخص في فيديو آخر. عند رفع فيديو جديد يبدأ الترقيم من جديد.

  • التتبّع المجهول: نخزّن رقم المسار وزمنه ودرجة الخطورة، دون أي بيانات تُعرّف الشخص.
  • الوصول للفيديو والدليل: محمي بالصلاحيات؛ الـ file_url يمرّ عبر endpoint يتحقق من المستخدم بدل رابط مباشر قابل للمشاركة.
  • سياسات الاحتفاظ: الفيديوهات وأدلة الوقائع لها مدة احتفاظ محدَّدة تُحذف بعدها (بما فيها الملفات من طبقة التخزين)، والوقائع تبقى كسجلات إحصائية.
  • الموافقة والغرض: الفيديو يُستخدم لغرض السلامة فقط، ولا يُعاد استخدامه لأي غرض آخر.

18.8 السجلات والنسخ الاحتياطي

الـ logs لا تحتوي كلمات مرور ولا توكنات ولا مسارات ملفات حساسة؛ نُسجّل المعرّفات والأخطاء فقط. ولحماية البيانات نأخذ نسخة احتياطية دورية من PostgreSQL (مثلاً pg_dump) مع نسخة من مجلّدات التخزين، ونختبر استرجاع نسخة واحدة فعلياً لأن نسخة لم تُجرَّب ليست نسخة.

خلاصة الفصل 18

ما تعلّمناه

فرّقنا بين المصادقة والتصريح، وشفّرنا كلمات المرور بـ bcrypt، وبنينا توكن JWT مع get_current_user وrequire_role، وأحكمنا الرفع وCORS ومنع SQL Injection، وأخرجنا الأسرار للبيئة، وثبّتنا خصوصية بلا تعرّف على الوجوه.

ما يجب تنفيذه

  • توليد SECRET_KEY عشوائي ووضعه في البيئة لا في الكود.
  • ربط المسارات الحساسة بـ Depends(require_role(...)).
  • التأكد أن كل مسار محمي يمرّ بـ get_current_user.
  • كتابة سياسة احتفاظ مكتوبة وضبط مدة الحذف.

المخرجات المتوقعة

  • جدول مستخدمين بكلمات مرور مشفَّرة فقط.
  • ملف .env.example بقيم Placeholder فقط.
  • توضيح مكتوب أن التتبّع مجهول وأن الـ track_id مؤقت.

كيف نتحقق من الإنجاز

  • لا يوجد نص صريح لكلمة مرور في قاعدة البيانات.
  • طلب مسار محمي بلا توكن يعيد 401 عند تفعيل المصادقة.
  • دور غير مصرّح له يحصل على 403.
  • لا يوجد سرّ مكتوب في الكود أو في Git.

أخطاء شائعة

  • تخزين كلمة المرور كنص صريح أو بـ md5.
  • السماح بـ CORS "*" في الإنتاج.
  • بناء استعلام SQL بتركيب نصي مباشر.
  • استخدام الـ track_id كهوية شخص أو ربطه بين فيديوهات.
  • وضع الأسرار في الكود أو رفع .env إلى Git.
