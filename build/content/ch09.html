CH09 · UPLOAD & STORAGE

رفع الفيديو وتخزين الملفات

كيف يستقبل النظام الفيديو ويتحقّق منه ويحفظه بأمان بعيداً عن قاعدة البيانات

هذا الفصل يغطّي أول خطوة في النظام: وصول ملف الفيديو إلى الخادم. الهدف أن نقبل الملفات الصحيحة فقط، ونمنع التكرار، ونحفظ الملف بمفتاح (storage key) آمن، مع بقاء بياناته الوصفية في PostgreSQL والملف نفسه في طبقة تخزين مستقلة.

9.1 الصيغ المدعومة وحدود الحجم

نُقيّد الرفع بقائمة امتدادات مسموح بها وحد أقصى للحجم، ونقرأ هذه القيم من متغيّرات البيئة لا من الكود، حتى يمكن تغييرها دون إعادة بناء المشروع.

9.2 التحقق من الملف في ثلاث طبقات

لا نثق باسم الملف وحده؛ نتحقّق في ثلاث مراحل متتالية:

  1. الامتداد: يجب أن يكون ضمن ALLOWED_VIDEO_EXTENSIONS.
  2. البصمة الرقمية للمحتوى (magic bytes): نقرأ أول بايتات الملف ونقارنها بتوقيع صيغ الفيديو المعروفة، فيُرفض ملف تنفيذي مُسمّى .mp4.
  3. فحص المحتوى: نفتح الملف بـ OpenCV لقراءة عدد الإطارات والأبعاد والمدة، وإن فشل الفتح نعتبره فيديو تالفاً ونرفضه.
لا تحفظ قبل التحقق

الخطأ الشائع هو كتابة الملف على القرص ثم التحقق منه. الأفضل تجميع القطع في الذاكرة أثناء الفحص، ثم حفظ الملف مرة واحدة فقط بعد اجتياز كل الفحوص.

9.3 أسماء الملفات الآمنة والمسارات والبيانات الوصفية

اسم الملف الأصلي لا يُستخدم أبداً على القرص. نولّد اسماً فريداً (stored_filename) من معرّف UUID مع الامتداد، ونبني المفتاح storage_key مثل uploads/<uuid>.mp4. هذا يمنع اجتياز المسار (path traversal) ويمنع تعارض الأسماء. الاسم الأصلي يبقى في original_filename للعرض فقط.

9.4 منع التكرار بـ checksum

أثناء القراءة نحسب sha256 للمحتوى ونخزّنه في checksum_sha256. قبل الحفظ نسأل القاعدة: هل يوجد فيديو بنفس البصمة؟ إن وُجد، نعيد السجل الموجود بدل تخزين نسخة مكرّرة، فنوفّر مساحة القرص ونمنع معالجة نفس الملف مرّتين. عمود البصمة مفهرس لهذا الاستعلام تحديداً.

9.5 طبقة Storage abstraction

شكل 9-1: طبقة التخزين تفصل الـ endpoint عن مكان الملف

الفائدة العملية أن الـ endpoint والـ worker لا يحتاجان تعديلاً عند تغيير مكان التخزين؛ يكفي تبديل التطبيق المختار حسب قيمة STORAGE_BACKEND.

backend/app/storage/base.pypython
# backend/app/storage/base.py
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import BinaryIO


@dataclass
class StoredObject:
    storage_key: str
    size_bytes: int
    content_type: str


class StorageBackend(ABC):
    """Common interface for local and object storage."""

    @abstractmethod
    def save(self, key: str, data: bytes, content_type: str) -> StoredObject: ...

    @abstractmethod
    def open_stream(self, key: str) -> BinaryIO: ...

    @abstractmethod
    def exists(self, key: str) -> bool: ...

    @abstractmethod
    def delete(self, key: str) -> None: ...

    @abstractmethod
    def url_for(self, key: str) -> str: ...
backend/app/storage/local.pypython
# backend/app/storage/local.py
from pathlib import Path
from typing import BinaryIO
from app.core.config import settings
from app.storage.base import StorageBackend, StoredObject


class LocalStorage(StorageBackend):
    """Filesystem storage used for local development."""

    def __init__(self, root: str | None = None) -> None:
        self.root = Path(root or settings.LOCAL_STORAGE_ROOT).resolve()
        self.root.mkdir(parents=True, exist_ok=True)

    def _path(self, key: str) -> Path:
        target = (self.root / key.lstrip("/")).resolve()
        if not str(target).startswith(str(self.root)):
            raise ValueError("storage key escapes the storage root")
        return target

    def save(self, key, data, content_type) -> StoredObject:
        path = self._path(key)
        path.parent.mkdir(parents=True, exist_ok=True)
        path.write_bytes(data)
        return StoredObject(key, len(data), content_type)

    def open_stream(self, key) -> BinaryIO:
        return open(self._path(key), "rb")

    def exists(self, key) -> bool:
        return self._path(key).is_file()

    def delete(self, key) -> None:
        self._path(key).unlink(missing_ok=True)

    def url_for(self, key) -> str:
        return f"/api/v1/evidence/file?key={key}"

9.6 نقطة الرفع POST /api/v1/videos

هذه هي النقطة التي يرفع إليها الـ Frontend الملف بصيغة multipart/form-data. تقرأ الملف على قطع، تتحقق من الحد الأقصى والحجم، تحسب البصمة، ثم تفوّض الحفظ والتحقق العميق إلى VideoService. الرد بحالة 201 يحمل كائن VideoOut.

backend/app/api/v1/endpoints/videos.pypython
# backend/app/api/v1/endpoints/videos.py (upload excerpt)
import hashlib
from fastapi import APIRouter, Depends, File, HTTPException, UploadFile, status
from app.core.config import settings
from app.dependencies import get_storage, get_video_service
from app.schemas.video import VideoOut

router = APIRouter(prefix="/videos", tags=["videos"])


@router.post("", response_model=VideoOut, status_code=status.HTTP_201_CREATED)
async def upload_video(file: UploadFile = File(...), storage=Depends(get_storage),
                 service=Depends(get_video_service)) -> VideoOut:
    ext = (file.filename or "").rsplit(".", 1)[-1].lower()
    if ext not in settings.ALLOWED_VIDEO_EXTENSIONS:
        raise HTTPException(status.HTTP_415_UNSUPPORTED_MEDIA_TYPE, "extension not allowed")

    digest, total, chunks = hashlib.sha256(), 0, []
    limit = settings.MAX_UPLOAD_MB * 1024 * 1024
    while chunk := await file.read(settings.UPLOAD_CHUNK_MB * 1024 * 1024):
        total += len(chunk)
        if total > limit:
            raise HTTPException(status.HTTP_413_REQUEST_ENTITY_TOO_LARGE, "file too large")
        digest.update(chunk)
        chunks.append(chunk)

    payload = b"".join(chunks)
    if not service.looks_like_video(payload[:64]):
        raise HTTPException(status.HTTP_400_BAD_REQUEST, "not a valid video file")

    video = await service.create_from_upload(
        original_filename=file.filename,
        content_type=file.content_type or "application/octet-stream",
        payload=payload, checksum=digest.hexdigest(), storage=storage)
    return VideoOut.model_validate(video)
ماذا يفعل VideoService؟

looks_like_video يفحص البصمة الرقمية، وcreate_from_upload يفتح الملف بـ OpenCV لقراءة المدة وعدد الإطارات، ثم يحفظه ويُنشئ صف videos بالحالة uploaded.

9.7 الوصول الآمن والتنظيف والاحتفاظ

  • الوصول للملفات: لا نكشف مسارات القرص مباشرةً. الـ Frontend يطلب GET /api/v1/evidence/{evidence_id}/file، والخادم يبثّ الملف (streaming) بعد التحقق من الصلاحية.
  • تنظيف الرفع المتروك: أي ملف كُتب ثم فشل إنشاء السجل يُحذف فوراً لتفادي الملفات اليتيمة.
  • سياسة الاحتفاظ: عند حذف فيديو (DELETE /api/v1/videos/{video_id}) نحذف سجله وملفاته وأدلته، مع إبقاء ما يفرضه الموقع من مدة احتفاظ قانونية.
  • الأدلة: عند إنشاء واقعة نقتطع صورة من الإطار ونحفظها في EVIDENCE_DIR ونربطها بجدول evidence (الفصل 12).

عند توليد الدليل نقتطع صورة JPEG من الإطار الذي وقعت فيه الواقعة عبر OpenCV بنوع محتوى image/jpeg. المقطع القصير (clip) اختياري في الـ MVP ويُضاف بنفس آلية التخزين لاحقاً. المهم أن الصورة والمقطع يُخزَّنان كملفّين مستقلّين، ولا يُقحمان داخل صف قاعدة البيانات.

خلاصة الفصل 9

ما تعلّمناه

كيف نستقبل الفيديو ونتحقّق منه في ثلاث طبقات، ونولّد مفتاح تخزين آمناً، ونمنع التكرار بالبصمة، ونفصل الكود عن مكان التخزين عبر واجهة StorageBackend.

ما يجب تنفيذه

  • كتابة app/storage/base.py و local.py.
  • ضبط MAX_UPLOAD_MB و ALLOWED_VIDEO_EXTENSIONS و UPLOAD_CHUNK_MB.
  • تنفيذ POST /api/v1/videos مع التحقق والبصمة.
  • تنفيذ نقطة البثّ الآمن للأدلة.

المخرجات المتوقعة

  • ملف فيديو محفوظ بمفتاح آمن وصف videos بحالة uploaded.
  • رفض واضح للملفات الكبيرة أو التالفة أو المكرّرة.

كيف نتحقق من الإنجاز

  • رفع نفس الملف مرتين لا يُنشئ نسختين على القرص.
  • ملف نصّي بامتداد .mp4 يُرفض.
  • الوصول المباشر لمسار القرص غير ممكن، والقراءة تتم عبر الـ API فقط.

أخطاء شائعة

  • استخدام اسم الملف الأصلي على القرص.
  • حفظ الملف قبل التحقق فيترك ملفات يتيمة.
  • كشف مسار التخزين للـ Frontend.
  • وضع بيانات اعتماد التخزين داخل الكود بدل متغيّرات البيئة.
