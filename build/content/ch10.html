CH10 · AI MODEL INTEGRATION

دمج الـ AI Models المتفق عليها

تحميل الـ checkpoints وتحويل مخرجاتها إلى صيغة داخلية موحّدة

لا نصمّم Models جديدة ولا نعيد التدريب؛ المهمة هي الدمج: تحميل كل checkpoint وتحويل مخرجاته إلى صيغة كشف واحدة تربط الفصول 11 و 12 و 13.

10.1 مبدأ أساسي: لا نعيد تصميم الـ Models

الـ Models الثلاثة (PPE، الحرائق والدخان، تتبّع الأشخاص) اختيرت سابقاً؛ دورنا أن نغلّفها بمحوّل (adapter) يوحّد مخرجاتها. تغيير المعمارية أو إعادة التدريب خارج النطاق.

قاعدة صارمة

لا نغيّر أوزاناً ولا نعيد تدريباً. إن لم يعمل الـ Model نسجّل الخطأ ونعالجه، ولا نستبدله في منتصف المشروع.

10.2 مسارات الـ checkpoints وكيف نستبدل الـ Placeholders

كل مسار من متغيّر بيئة وقيمته الافتراضية placeholder؛ نستبدله بمسار حقيقي بمجرد تسليم الملف، دون تعديل كود.

جدول 10-1: الـ Placeholders وكيف تُستبدل
الـ Placeholderالمتغيّركيف نستبدله
<PPE_MODEL_CHECKPOINT_PATH>PPE_MODEL_PATHنضع مسار ملف أوزان الـ PPE داخل MODEL_DIR
<FIRE_SMOKE_MODEL_CHECKPOINT_PATH>FIRE_SMOKE_MODEL_PATHمسار أوزان الحرائق والدخان
<PERSON_TRACKER_CHECKPOINT_PATH>PERSON_TRACKER_PATHمسار أوزان تتبّع الأشخاص
<MODEL_VERSION>ثابت داخل المحوّليُستبدل برقم إصدار الـ Model بعد التدريب، ويُسجَّل في كل كشف

10.3 اختيار الجهاز: CPU أم GPU

المتغيّر MODEL_DEVICE يحدّد cpu أو cuda: نطوّر على cpu للجميع، ونستخدم cuda عند توفّر كرت لتقليل الزمن. الكود لا يتغيّر.

ذاكرة الـ GPU

إذا نفدت ذاكرة كرت الرسوم، نُصغّر INFERENCE_IMG_SIZE أو نعود إلى cpu. لا نُشغّل عدّة عمليات inference ثقيلة في نفس الوقت على نفس الجهاز.

10.4 إعدادات الـ Inference

كل إعدادات التشغيل تأتي من core/config.py، فلا توجد أرقام مكتوبة داخل الكود.

backend/app/core/config.pypython
# backend/app/core/config.py (model settings excerpt)
from pydantic_settings import BaseSettings


class Settings(BaseSettings):
    MODEL_DIR: str = "models"
    PPE_MODEL_PATH: str = "<PPE_MODEL_CHECKPOINT_PATH>"
    FIRE_SMOKE_MODEL_PATH: str = "<FIRE_SMOKE_MODEL_CHECKPOINT_PATH>"
    PERSON_TRACKER_PATH: str = "<PERSON_TRACKER_CHECKPOINT_PATH>"
    MODEL_DEVICE: str = "cpu"
    DETECTION_CONF_THRESHOLD: float = 0.25
    NMS_IOU_THRESHOLD: float = 0.45
    INFERENCE_IMG_SIZE: int = 640
    PERSIST_ALL_DETECTIONS: bool = False
    PPE_CONF_THRESHOLD: float = 0.40
    FIRE_CONF_THRESHOLD: float = 0.40
    SMOKE_CONF_THRESHOLD: float = 0.40


settings = Settings()

INFERENCE_IMG_SIZE حجم الإطار قبل الـ Model، وNMS_IOU_THRESHOLD يحذف الصناديق المتداخلة (Non-Maximum Suppression)، وDETECTION_CONF_THRESHOLD حدّ الثقة العام. ولأن كل Model مختلف، توجد عتبات أدق لكل نوع (PPE_CONF_THRESHOLD، FIRE_CONF_THRESHOLD، SMOKE_CONF_THRESHOLD).

10.5 خريطة أسماء الأصناف

كل checkpoint يعيد أسماء أصناف خاصة به، نخريطها (class map) إلى أسماء داخلية واحدة ليتعامل معها الفصل 12. الصنف غير المعروف نُبقيه باسمه الأصلي.

10.6 الصيغة الموحّدة للكشف

العقد الداخلي: كل محوّل يعيد قائمة Detection بنفس حقول المواصفة (الفصل 4)، والواجهة DetectionModel تفرض load و predict.

backend/app/ai/base.pypython
# backend/app/ai/base.py
from dataclasses import dataclass
from typing import Protocol
import numpy as np


@dataclass
class Detection:
    """Normalized detection shared by every model adapter."""
    class_name: str
    confidence: float
    bbox: tuple[int, int, int, int]  # x1, y1, x2, y2
    frame_number: int
    timestamp_seconds: float
    model_name: str
    model_version: str
    track_id: int | None = None


class DetectionModel(Protocol):
    name: str
    version: str

    def load(self) -> None: ...

    def predict(self, frame: np.ndarray, frame_number: int,
                timestamp_seconds: float) -> list[Detection]: ...

10.7 الخدمات الأربع

نبني أربع خدمات لكل منها مسؤولية واحدة واضحة:

  • PPEDetectionService — كشف معدات الوقاية (ملف app/ai/ppe_detector.py).
  • FireSmokeDetectionService — كشف الحرائق والدخان (app/ai/fire_smoke_detector.py).
  • PersonTrackingService — تتبّع الأشخاص بـ ByteTrack عبر model.track (app/ai/person_tracker.py).
  • SafetyRuleEngine — طبقة القواعد التي تُستخدم مخرجات الخدمات الثلاث (الفصل 12، ملف app/ai/rules.py).

10.8 محوّل الـ PPE كنموذج للتطبيق

هذا الملف يوضّح النمط الذي تتبعه بقية الخدمات: تحميل الـ checkpoint مرة واحدة، ثم ترجمة كل صندوق إلى Detection بأسماء موحّدة.

backend/app/ai/ppe_detector.pypython
# backend/app/ai/ppe_detector.py
from ultralytics import YOLO
from app.ai.base import Detection, DetectionModel
from app.core.config import settings

# Map raw checkpoint labels to agreed internal class names.
PPE_CLASS_MAP = {
    "helmet": "helmet",
    "no_helmet": "no_helmet",
    "vest": "vest",
    "no_vest": "no_vest",
    "person": "person",
}


class PPEDetectionService(DetectionModel):
    """Adapter for the agreed PPE checkpoint (loaded, not redesigned)."""

    name = "ppe_detector"
    version = "<MODEL_VERSION>"  # replace with the real trained version

    def __init__(self) -> None:
        self._model: YOLO | None = None

    def load(self) -> None:
        self._model = YOLO(settings.PPE_MODEL_PATH)
        self._model.to(settings.MODEL_DEVICE)

    def predict(self, frame, frame_number, timestamp_seconds) -> list[Detection]:
        if self._model is None:
            raise RuntimeError("PPEDetectionService.load() was not called")
        results = self._model.predict(
            frame, imgsz=settings.INFERENCE_IMG_SIZE,
            conf=settings.PPE_CONF_THRESHOLD, iou=settings.NMS_IOU_THRESHOLD,
            device=settings.MODEL_DEVICE, verbose=False)
        detections: list[Detection] = []
        for box in results[0].boxes:
            raw = self._model.names[int(box.cls.item())]
            detections.append(Detection(
                class_name=PPE_CLASS_MAP.get(raw, raw),
                confidence=float(box.conf.item()),
                bbox=tuple(int(v) for v in box.xyxy[0].tolist()),
                frame_number=frame_number, timestamp_seconds=timestamp_seconds,
                model_name=self.name, model_version=self.version))
        return detections

10.9 سجل الـ Models model_registry

لتفادي تحميل ثقيل متكرّر، يضمن السجل نسخة واحدة من كل خدمة عبر lru_cache.

backend/app/ai/model_registry.pypython
# backend/app/ai/model_registry.py
from functools import lru_cache
from app.ai.base import DetectionModel
from app.ai.ppe_detector import PPEDetectionService
from app.ai.fire_smoke_detector import FireSmokeDetectionService
from app.ai.person_tracker import PersonTrackingService


@lru_cache(maxsize=1)
def get_ppe_detector() -> DetectionModel:
    model = PPEDetectionService()
    model.load()
    return model


@lru_cache(maxsize=1)
def get_fire_smoke_detector() -> DetectionModel:
    model = FireSmokeDetectionService()
    model.load()
    return model


@lru_cache(maxsize=1)
def get_person_tracker() -> DetectionModel:
    model = PersonTrackingService()
    model.load()
    return model

10.10 المحوّل التجريبي demo_adapter للاختبار فقط

لاختبار خط المعالجة قبل توفّر الـ checkpoints نكتب محوّلاً وهمياً يعيد صناديق ثابتة دون تشغيل أي Model. هذا المحوّل وهمي صراحةً ولا يُستخدم في العرض النهائي ولا في أي قياس دقة.

backend/app/ai/demo_adapter.pypython
# backend/app/ai/demo_adapter.py
# WARNING: this adapter is FAKE. It runs no model and returns fixed boxes.
# Use it ONLY to test the pipeline when real checkpoints are missing.
from app.ai.base import Detection, DetectionModel


class DemoDetectionService(DetectionModel):
    """Deterministic fake detections for pipeline testing only."""

    name = "demo_adapter"
    version = "demo"

    def load(self) -> None:
        return None

    def predict(self, frame, frame_number, timestamp_seconds) -> list[Detection]:
        height, width = frame.shape[:2]
        # One fixed person box in the centre of the frame.
        return [Detection(
            class_name="person", confidence=0.50,
            bbox=(width // 4, height // 4, width // 2, height // 2),
            frame_number=frame_number, timestamp_seconds=timestamp_seconds,
            model_name=self.name, model_version=self.version, track_id=1)]
خطر الخلط

لا تترك demo_adapter يعمل خارج وضع الاختبار؛ يجب أن يكون تبديله صريحاً عبر الإعدادات وأن يظهر في السجل أن الـ Model وهمي.

10.11 الأداء والموارد ومعالجة الأخطاء

  • الدفعات: نجمع عدّة إطارات في دفعة (batch) لتسريع الـ inference، ونعود للإطار المفرد عند ضيق الذاكرة.
  • التسخين warm-up: تشغيل الـ Model على إطار وهمي عند التحميل لتفادي بطء أول إطار.
  • الموارد: الـ checkpoint يُحمَّل مرة واحدة عبر السجل ويُعاد استخدامه.
  • الأخطاء: كل predict داخل try/except؛ خطأ إطار لا يُسقط الوظيفة.

10.13 تسجيل الإصدار وإعادة الإنتاج، والدقة

كل كشف يحمل model_name و model_version، وإصدار الحزمة في processing_jobs.model_bundle_version، فتُفسَّر نتائج أي وظيفة لاحقاً. الدقة تُقاس على مجموعة اختبار مستقلة ولا تُفترض؛ الجدول يبقى فارغاً حتى تنتهي التجربة.

خلاصة الفصل 10

ما تعلّمناه

كيف نغلّف الـ Models المتفق عليها بمحوّلات موحّدة، وكيف نحوّل مخرجاتها إلى كائن Detection واحد، وكيف نُدير التحميل والإعدادات والأخطاء.

ما يجب تنفيذه

  • كتابة app/ai/base.py بالـ Detection و DetectionModel.
  • كتابة المحوّلات الثلاثة وسجل الـ Models.
  • استبدال كل placeholder بمسار حقيقي عند توفّر الـ checkpoints.
  • إبقاء demo_adapter للاختبار فقط.

المخرجات المتوقعة

  • خدمة تُعيد قائمة Detection موحّدة من أي Model.
  • الـ checkpoint يُحمَّل مرة واحدة لكل عملية.

كيف نتحقق من الإنجاز

  • تشغيل demo_adapter يُنتج كشوفات ويُكمل خط المعالجة دون Models حقيقية.
  • كل كشف يحمل model_name و model_version.
  • لا يوجد رقم دقة في التوثيق بلا قياس.

أخطاء شائعة

  • إعادة تدريب أو استبدال Model في منتصف التكامل.
  • تحميل الـ checkpoint في كل استدعاء بدل مرة واحدة.
  • استخدام demo_adapter في العرض النهائي.
  • كتابة مسارات الأوزان داخل الكود بدل متغيّرات البيئة.
